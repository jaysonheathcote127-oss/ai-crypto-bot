# Project continuity

The user explicitly requests durable local records so valuable information is not lost between conversations.

At the start of every chat working in this folder, read `memory/PROJECT_MEMORY.md` and `memory/CONVERSATION_LOG.md`. Read linked project documents as needed before making claims about previous work.

During work, record meaningful user requirements, decisions and their reasons, corrections, findings with evidence, completed changes, validation, unresolved questions, and next steps. Update after major milestones and before the final response; do not rely only on the chat context. Record interrupted work as incomplete. Keep secrets, API keys, passwords, and credentials out of these records.

Keep `memory/PROJECT_MEMORY.md` concise and current. Append dated entries to `memory/CONVERSATION_LOG.md`; preserve old entries and append corrections rather than silently rewriting history. Use Europe/London dates. Include source paths or chat identifiers when available. Distinguish direct user statements, verified observations, and assumptions. Never invent missing history or describe summaries as verbatim transcripts.

These instructions apply to this project. They do not create an automatic recording service, guarantee that every future agent follows them, or give access to every other chat. When relevant older history is unavailable, explicitly record that gap and recover it from accessible sources where possible. Do not claim a local disk copy is an independent backup.
